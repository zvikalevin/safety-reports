# דיווח מפגעי בטיחות במפעל

אפליקציית web פשוטה לדיווח מפגעי בטיחות: העובד סורק קוד QR מהלוח מודעות, מצלם את המפגע, ממלא טופס קצר ושולח - **בלי להתחבר לשום חשבון** (לא Google, לא Microsoft, לא הרשמה בכלל). למנהל/מפקח יש ממשק ניהול נפרד המוגן בסיסמה, לצפייה בכל הדיווחים ועדכון סטטוס טיפול.

## מה יש כאן

- `public/index.html` - טופס הדיווח שהעובדים רואים (בעברית, מובייל-first)
- `public/admin.html` - ממשק הניהול (מוגן בסיסמה)
- `server.js` - שרת Node.js/Express שמקבל דיווחים ושומר אותם
- `lib/excel.js` - בונה קובץ Excel מרכזי מכל הדיווחים, כולל תמונות מוטמעות
- `lib/mailer.js` - שולח מייל אוטומטי עם קובץ ה-Excel בכל דיווח חדש
- `data/reports.json` - "מסד הנתונים" - קובץ JSON פשוט (נוצר אוטומטית)
- `data/reports.xlsx` - קובץ ה-Excel המרכזי (נוצר/מתעדכן אוטומטית)
- `data/uploads/` - תמונות המפגעים שהועלו
- `poster/generate-poster.js` - סקריפט שיוצר פוסטר A4 עם קוד QR להדפסה

**למה ככה?** בלי מסד נתונים חיצוני ובלי תלות בענן ספציפי (Firebase/AWS וכו') - קל להריץ בכל מקום: שרת פנימי במפעל, מחשב ישן, או שירות אחסון חינמי.

## הרצה מקומית (לבדיקה)

```bash
npm install
cp .env.example .env
# ערוך את .env והחלף את ADMIN_PASSWORD לסיסמה שלך
npm start
```

- טופס דיווח: http://localhost:3000
- ממשק ניהול: http://localhost:3000/admin.html

## פריסה לאינטרנט - כדי שעובדים יוכלו לגשת מהטלפון שלהם

**המלצה: Render.com** - נרשמים עם אימייל בלבד (בלי חובה לחשבון Google/Microsoft), יש תוכנית חינמית, ותומך ב-HTTPS אוטומטית (חשוב כדי שהמצלמה בטלפון תעבוד חלק).

שלבים:
1. העלה את התיקייה הזו לריפו ב-GitHub (או השתמש ב"Deploy from folder" אם הספק תומך).
2. ב-Render: New → Web Service → חבר את הריפו.
3. הגדרות בנייה: `npm install` | הרצה: `npm start`.
4. תחת Environment Variables הוסף `ADMIN_PASSWORD` עם סיסמה חזקה.
5. אחרי הפריסה תקבל כתובת כמו `https://xxx.onrender.com` - זו הכתובת שהעובדים יגיעו אליה.

חלופות דומות (גם הן ללא חובת חשבון Google/Microsoft, הרשמה באימייל בלבד): Railway.app, Fly.io, או שרת פנימי קיים ברשת המפעל (אם העובדים משתמשים ב-WiFi פנימי בלבד, אפשר גם מחשב מקומי ברשת המפעל בלי חשיפה לאינטרנט הרחב).

⚠️ **חשוב**: תמונות ודיווחים נשמרים בקובץ מקומי בשרת (`data/`). בשירותי אחסון "בחינם" רבים (כולל Render tier חינמי) הדיסק הוא **זמני** ועלול להימחק בכל דיפלוי/הפעלה מחדש. לשימוש רציני בייצור מומלץ: לשדרג לתוכנית עם דיסק קבוע (Render Persistent Disk וכו'), או לגבות את תיקיית `data/` באופן קבוע.

## יצירת פוסטר QR ללוח המודעות

אחרי שהאפליקציה פרוסה ויש לך כתובת (URL):

```bash
node poster/generate-poster.js https://your-app-url.onrender.com
```

זה ייצור `poster/poster.html` ו-`poster/qrcode.png`. פתח את `poster.html` בדפדפן, הדפס (Ctrl+P) ושמור כ-PDF או הדפס ישירות - גודל A4 מוכן לתלייה.

## ממשק הניהול

כתובת: `/admin.html` (למשל `https://your-app-url.onrender.com/admin.html`)

- מוגן בסיסמה שהגדרת ב-`ADMIN_PASSWORD`.
- מציג את כל הדיווחים עם תמונה, מיקום, רמת דחיפות, תיאור ושם מדווח (אם צוין).
- ניתן לסנן לפי סטטוס / רמת דחיפות / מיקום.
- ניתן לעדכן סטטוס לכל דיווח: פתוח → בטיפול → טופל.
- לחיצה על תמונה מגדילה אותה.
- כפתור **"הורד Excel"** למעלה - מוריד באופן ידני את קובץ ה-Excel המרכזי המעודכן בכל רגע נתון.

**הערת אבטחה**: ההגנה כרגע היא סיסמה משותפת פשוטה - מספיקה לשימוש פנים-ארגוני בסיסי. אם רוצים הרשאות פר-משתמש, יומן פעולות (audit log), או הצפנה נוספת - אלה שיפורים עתידיים אפשריים.

## דיווח אוטומטי במייל + Excel (כדי לשתף בקלות עם אחרים)

מי שלא רוצה להתחבר לממשק הניהול כדי לראות דיווחים, יכול פשוט לקבל אותם במייל: **בכל דיווח חדש שנשלח, המערכת בונה קובץ Excel מעודכן עם כל הדיווחים (כולל תמונות מוטמעות בתוך הגיליון) ושולחת אותו כקובץ מצורף במייל** לכתובות שתגדירו - כולל תקציר הדיווח החדש בגוף המייל. את המייל אפשר להעביר הלאה (Forward) ב-Outlook לכל מי שצריך, בלי לתת לו גישה למערכת בכלל.

אם לא מגדירים את פרטי המייל, המערכת ממשיכה לעבוד כרגיל (הדיווחים נשמרים, ה-Excel מתעדכן) - היא פשוט מדלגת על שליחת המייל ורושמת על כך הודעה ביומן השרת.

### הגדרת שליחה דרך Outlook / Office 365

יש שתי אפשרויות, לפי סוג החשבון:

**חשבון Outlook אישי (outlook.com / hotmail.com):**
1. היכנסו לחשבון ב-https://account.microsoft.com/security
2. תחת "אפשרויות אבטחה מתקדמות" צרו **App Password** (סיסמת אפליקציה) ייעודית - לא את הסיסמה הרגילה שלכם.
3. ב-`.env`, מלאו:
   ```
   SMTP_HOST=smtp.office365.com
   SMTP_PORT=587
   SMTP_SECURE=false
   SMTP_USER=your-email@outlook.com
   SMTP_PASS=<ה-App Password שיצרתם>
   MAIL_FROM=your-email@outlook.com
   MAIL_TO=manager@example.com,safety@example.com
   ```

**חשבון ארגוני (Microsoft 365 / Office 365 של החברה):**
1. ודאו מול ה-IT שלכם ש-**SMTP AUTH מופעל** עבור תיבת הדואר (ב-Microsoft 365 admin center זה כבוי כברירת מחדל בחשבונות חדשים - זו הסיבה השכיחה ביותר לכשלון שליחה).
2. אם יש אימות דו-שלבי (MFA) על החשבון, תזדקקו ל-App Password כמו למעלה (ולא לסיסמה הרגילה).
3. מלאו את `.env` באותו אופן, עם הכתובת הארגונית שלכם ב-`SMTP_USER` ו-`MAIL_FROM`.

**חלופה: Gmail** - אם נוח לכם יותר, אפשר גם `SMTP_HOST=smtp.gmail.com` עם App Password של גוגל (נדרש MFA מופעל בחשבון).

אחרי שמילאתם את הפרטים ושמרתם את `.env`, הפעילו מחדש את השרת (`npm start`) - בלוג יופיע אישור אם ההגדרות תקינות, או הודעת שגיאה מפורטת אם לא.

**הערת אבטחה**: `SMTP_PASS` הוא סוד רגיש בדיוק כמו `ADMIN_PASSWORD` - הוא נשמר רק בקובץ `.env` המקומי שלכם (לא מועלה ל-Git, לא נחשף ללקוח). מומלץ להשתמש ב-App Password ולא בסיסמת הכניסה הרגילה לחשבון, כדי שאם הוא ידלוף, ניתן יהיה לבטל רק אותו בלי לשנות את סיסמת החשבון כולו.

## שדות הטופס

| שדה | חובה | הערות |
|---|---|---|
| תמונה | כן | צילום ישיר מהמצלמה או בחירה מהגלריה, עד 8MB (גודל תמונה טיפוסית מטלפון) |
| מיקום במפעל | כן | טקסט חופשי עם הצעות אוטומטיות |
| רמת דחיפות/סיכון | כן | נמוך / בינוני / גבוה / קריטי |
| תיאור | כן | טקסט חופשי |
| שם מדווח | לא | ניתן להשאיר ריק - דיווח אנונימי |

## רעיונות לשיפור עתידי

- הוספת מיקום GPS אוטומטי מהטלפון בזמן הדיווח
- שליחת מייל מיידי (בנוסף לקובץ ה-Excel) רק עבור דיווחים ברמת "קריטי", כדי לא להציף תיבת דואר בדיווחים שגרתיים
- PWA מלא עם אייקון על מסך הבית וגישה גם ללא רשת (offline)
- שליחת וואטסאפ/SMS כערוץ נוסף למייל
